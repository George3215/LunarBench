# 独立目标恢复工作流

顺序：合并地形并严格验收 → VLMnav原生环境与恢复验证 → NaVILA原生环境与恢复验证 → 两者通过后才接入MuJoCo并执行12条件。没有迁移LunarBench，没有重写已完成实验。

阈值在批量搜索前锁定于PROTOCOL.json。G1需要有效RGB目标像素；G2需要实际安全运动后连续丢失；G3需要目标仍处于相机视野且射线命中真实地形/障碍；G4需要实际执行安全动作恢复可见性。拒绝记录和搜索预算同样保存。动态石头的几何检查使用当前MuJoCo状态，不使用静态高度oracle替代。

旧版31个已验证场景和新版38个设计作为69个独立来源候选保留，按A–E分类；不将相同名称当作同一物理配置。F类留作独立泛化设计，当前不伪造复合场景或验收结果。E类窗口是否需要历史信息，需要额外配对审计，不能仅凭窗口几何就声称成立。

G4用于恢复可见性，最终到达目标是另一个指标；正式Final Task Success仍要求目标可见、深度测距<1m并持续满足条件。实际模型输入与验收真值分目录，oracle路径不得送入模型上下文。
