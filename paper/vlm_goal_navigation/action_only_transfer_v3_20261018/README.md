# TASK3 空间模型迁移：仅动作输出接口

## 预先固定的问题与解释边界

原 v2 同 prompt 实验五个模型均已完成22场景。SpatialReasoner 22/22、Spatial-Interactor 21/22、SpatialRGPT 19/22 以 invalid_model_output 结束；这不能直接说明模型没有空间能力。

本组检验：使用所有模型共有的更简单动作接口，是否能消除结构化输出障碍，并观察真实闭环到达与重观测表现。此组不是新的学习方法，也不能证明空间微调产生了因果收益。

## 固定设置

- 同一22个 V4 admitted 场景、初始姿态、目标、地形和可见到遮挡的动作前缀；与旧实验逐例比较首帧RGB、丢失帧RGB和丢失姿态。
- 所有模型共享同一个新 actor system prompt；保留图像/深度解释、动作定义、关键帧、理想自身里程计、最近6次实际动作效果和自己的首帧计划。
- 首帧计划沿用 v2 PLAN_SYSTEM、640 token预算和解析规则；失败保留 null，不补造计划。
- Actor 只输出一个合法动作名，最多16 token，greedy；6种运动动作，满足传感器停止门槛才加入 STOP。
- 整个动作名通过该模型 tokenizer 的合法 token 路径约束；保留候选 token 的原相对 logits。没有路线规划器或运动兜底替模型选择动作。
- 不再要求每步输出可见性、距离、置信度、证据引用、计划更新或重现距离预测；不为这些项目补值或计算准确率。内部空 evidence 列表仅兼容日志接口。
- 正式64自主动作预算、同样2场景批执行、每帧面积上限/native视觉预处理沿用该模型适配设置。
- STOP：当前RGB红像素>=20，且有限0<红区域距离<1m。到达仍由评估器连续3个10Hz采样确认，与VLM主动STOP分开统计。
- 绝不向模型提供目标真实坐标、真实地图、评估器字段或参考路线；路径图的目标标记仅作事后评估。

## 顺序、准入与记录

先对五个模型各运行 barrier_a0、pit_a0 两场、每场4动作的接口短测试；短测试不计入正式成功率。仅当两场都有自主动作且无格式/资源失败、请求审计无禁用字段时接入正式22场景。

正式顺序：Qwen3-VL-8B、SpatialReasoner、Spatial-Interactor、SpatialRGPT、RoboBrain2.5-8B-NV。先完成新Qwen基线；所有模型使用同一新协议，不与旧协议拼接成一个排行榜。

正式报告到达、重观测、重观测但未到达、成功场景、前进即可成功的场景、非法STOP、转圈/低位移和终止类型。只有全部22场景及配对审计通过才给最终配对比较；按地形族重采样描述不确定性。

与 v2 的变化同时包括 actor prompt、输出约束、输出预算和取消可选计划更新，因此跨版本差异是协议层面比较，不是单独某个组件的因果消融。

原始RGB-D、网络输入、token、输出、动作、状态和评估采样保留本机；GitHub存协议、源码、回合结果、精简逐步证据、汇总和轨迹图。每完成4个正式回合及每模型结束后更新分析和备份。远端推送失败重试并记录，不使本地推理中止。

`QUEUE_STATUS.json` 为实时队列，`REPORT.md` 与 `metrics.json` 为阶段分析。根目录 `STOP` 在动作边界暂停并阻止下一模型，不移除历史STOP或覆盖已有回合。

## 局限

红球目标、理想模拟RGB-D/里程计、单次greedy和相关的22场景，不代表开放词汇、真机或噪声传感器效果。准入只证明目标可恢复可见，不保证所有场景都有已认证的<1m到达路线。SpatialRGPT仍使用通用多图输入，不代表其原生区域/深度分支完整能力。

## 执行附记：SpatialRGPT 接口修复

首轮SpatialRGPT短测试在执行自主动作前触发 `Invalid action trie prefix: [128000]`。原生Transformers 4.37.2在inputs_embeds生成时自动加入BOS，动作约束需从该起始token之后开始。已用同版本、真实tokenizer和随机微型Llama CPU生成检查确认修复；这只是兼容性检查，不是该模型GPU/导航测试。

其余四个模型已通过两场短测试，先按原预算继续正式评测。SpatialRGPT安排在当前队列退出后单独重试，失败目录和日志归入interface_failures，保留不覆盖；通过短测试才执行正式22场景。调度顺序改变不改变模型prompt、场景或动作预算。等待状态见FOLLOWUP_STATUS.json。
