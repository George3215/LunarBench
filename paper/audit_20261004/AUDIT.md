## 4. 相机补充实验

固定六个恢复动作：前进、后退、左平移、右平移、左转、右转；每个动作 3 s。控制器为既有 `go2rl`，相机为**运行时注入的机身 MuJoCo RGB-D**，非原生实机相机。目标是唯一红色球标记，检测器是颜色阈值，不是开放世界语义检测器。

正式分辨率 320×240，10 Hz 采样；最终严格协议中颜色亮度条件为 R>50 且 R>1.5G、R>1.5B；至少 3 个目标颜色像素为一次检测，连续三帧检测后、连续三帧颜色像素为零才认为进入 loss。只有这种由动力学执行产生的 loss 状态才评价恢复。恢复成功要求连续三帧检测且机器人保持 upright≥0.25、在边界内。接近过程是使用场景定义的固定诱导程序；不是被评策略。恢复策略不读场景坐标或 oracle。

先做的 160×120 两场景试跑发现目标只有 1–2 像素，保留在 `camera_pilot.json`；一个被中止的低分辨率全量运行保存在 `camera_lowres_incomplete.json`。随后提高分辨率，又在图像复核和控制器状态检查后固定严格配置，写入 `strict_camera/camera_rollouts.protocol.json`；没有事后按策略结果删除世界。`strict_camera/camera_rollouts.json` 是最终完整轨迹，`strict_camera/frames/` 是 seen/lost/reacquired 图像。所有 24 个候选世界与未通过前置条件的世界都必须报告。

在同一个 loss 快照上逐个物理执行六个动作。均匀随机基线的单步期望由六个实测结果精确平均，不需要抽三个 seed 估计。学习评分器使用 RGB-D 摘要、最后图像检测记忆与动作 one-hot；不使用世界坐标。留出整对构造组，固定随机森林参数与三个模型 seed。结果只称**单步离线分支评价**，不是部署后的在线 RSR@10。

最终数字见 `strict_camera/camera_analysis.json` 和 `RESULTS.md`；根目录同名 JSON 是试跑归档，不是最终结果。阈值 1/3/10 的分析是在主阈值 loss 状态上变更恢复判据的**条件敏感性分析**，不能称完整不同阈值闭环重跑。组 bootstrap 反映该设计场景集合的不确定性，不代表自然环境总体置信区间。不同模型 seed 是拟合重复，不是三次独立物理试验。

## 8. 采集过程发现并修复的观测副作用

最初有/无观察器对照出现最终广义坐标最大差 0.02735、路径差约 0.0091 m。进一步检查发现 TorchScript 导出策略自身有 history 张量和 reset 方法，但外层 Go2RL.reset 只清空 action，导致分支间历史残留；不能把该对照差异单独归因于相机。现已同时清空导出模型内部历史，并将渲染移到独立 MjData 副本，避免观察器修改 live 状态。此前分支结果可能受候选执行顺序影响。因此，本目录根部最初的 camera_rollouts/analysis 仅保留为试跑诊断，不能作为最终论文数据。修正后相机在私有 MjData 副本上 mj_copyData + mj_forward；最终正式数据转入 strict_camera/。另一次中止的严格试跑保存在 strict_camera_observer_mutation_incomplete/。check_observer.py 对同一快照有/无相机观察器的轨迹作直接一致性检查。

最终实验明确每个三秒原语从一致的控制器冷启动状态执行（内部历史与外层动作同时归零），而不是延续接近阶段的隐藏状态。这保证候选分支比较公平，但限制了对连续在线步态的推广。运行重力为 [0,0,-9.81] m/s²、物理步长 0.002 s，不能宣称月球重力验证。

## 10. 最终结果与判断

23 个世界、15 个构造组：固定前进 0.7391，精确随机期望 0.3623；当前图像摘要+动作评分器 0.7246，增加最后检测记忆仍为 0.7246（均为三个拟合 seed 平均）。评分器相对前进差 -0.0145，构造组 bootstrap 区间 [-0.050,0.000]。图像与几何在 4140 个恢复采样帧上一致率 91.67%，但不是完全相等的测量。仅前进/左/右的分支上界 18/23=0.7826，六动作上界 23/23=1.000；上界不是部署策略。

因此，任务有合理应用意义，但当前场景及结果不能证明历史必要、学习规划更优或通用新方法的创新性。后续应先独立锁定能区分强简单基线的真实丢失状态，再谈扩模型。最终英文稿如实保留负结果。
